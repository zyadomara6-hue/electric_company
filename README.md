# 🔌 Backend — إعداد Supabase (خطوة بخطوة)

الموقع دلوقتي بيستخدم **Supabase** كـ Backend (قاعدة بيانات + تسجيل دخول للوحة التحكم + تخزين صور + CMS).

## 🏁 1) إنشاء حساب ومشروع

1. ادخل على https://supabase.com
2. اعمل **Sign Up** (مجاني)
3. اضغط **New Project** واختر منطقة قريبة منك (مثل `eu-central-1`)

## 🔑 2) مفاتيح الاتصال

✅ **تم الربط مسبقًا** — ملف `supabase-config.js` يحتوي بالفعل على:
- Project URL: `https://fcvjpdvrcptogvzftgep.supabase.co`
- Publishable/anon key: `sb_publishable_...`

> هذا المفتاح عام (anon) مخصص للاستخدام في الواجهة الأمامية — آمن.
> ⚠️ **لا تضع أبدًا** service_role أو أي Secret key هنا أو في أي ملف Frontend.

## 🗄️ 3) إنشاء الجداول

1. من الشريط الجانبي: **SQL Editor → New query**
2. الصق محتوى ملف `schema.sql` كاملًا
3. اضغط **Run**

## 🧑💼 4) إنشاء حساب الأدمن (Sign-in)

1. من الشريط الجانبي: **Authentication → Users**
2. اضغط **Add user** وأنشئ البريد وكلمة المرور لهذه اللوحة
3. (اختياري وأكثر أمانًا) **Authentication → Providers → Email** فعّل "Confirm email"

## 📦 5) إنشاء Storage لرفع الصور

1. من الشريط الجانبي: **Storage → New bucket**
2. الاسم: `project-images`
3. **Public** → فعّلها
4. من تبويب **Policies** أضف:
   - Policy name: `Allow public read`
   - Operation: `SELECT`
   - Target roles: `anon`
   - باستخدام: `CREATE POLICY "Allow public read" ON storage.objects FOR SELECT USING (bucket_id = 'project-images');`

## ➕ (مهم) نقل المشاريع الثابتة الستة إلى قاعدة البيانات

> **الموقع بقى يستخدم Supabase كمصدر أساسي (Single Source of Truth) للمشاريع.**
> المشاريع الستة القديمة (اللي كانت مكتوبة كـ HTML ثابت) محتاجة تُنقل مرة واحدة إلى جدول `projects`.

من **SQL Editor** شغّل محتوى ملف **`seed-projects.sql`** كاملًا (مرة واحدة فقط).

ده هيضيف المشاريع الستة دي لجدول `projects`:
1. تأسيس كهرباء فيلا
2. لوحة كهرباء مصنع
3. عدادات الكهرباء
4. مشروع 4 (فيديو)
5. مشروع 5 (فيديو)
6. مشروع 6 (فيديو)

> **الملف آمن للتكرار (Idempotent):** لو شغّلته أكتر من مرة مش هيضيف أي مشروع مكرر (المنع حسب العنوان).
> الصور محفوظة بروابطها النسبية الأصلية (`images/...`) فمفيش أي رابط مكسور.
> بعد النقل، الموقع هيقرأ المشاريع من قاعدة البيانات تلقائيًا ويعرضها **بدون أي تكرار** مع الكروت الثابتة القديمة.

### ⚠️ ملاحظة عن الكروت الثابتة القديمة
- سيب الكروت الستة في `projects.html` **كاحتياط (Fallback)**.
- طالما فيه بيانات في جدول `projects`، الموقع **بيستبدلها** ويعرض من قاعدة البيانات فقط (مفيش تكرار).
- ولو جدول `projects` فاضي (قبل النقل)، الموقع هيعرض الكروت الثابتة عادي.
- تعديلات اللوحة (إضافة/تعديل/إخفاء/حذف) هتظهر على الموقع بعد تحديث الصفحة مباشرة بدون أي تعديل في الكود.

## 🔒 الأمان (RLS + Permissions)

> **الزائر (anon) يقدر فقط:**
> - يقرأ المشاريع النشطة (للعرض على الموقع)
> - يرفع/save رسالته في جدول `leads` (Insert)
> - يقرأ ملفات الصور من storage (للعرض)

> **الزائر (anon) ممنوع تمامًا من:**
> - قراءة/تعديل/حذف رسائل العملاء (`leads`) — بيانات حساسة محمية
> - إضافة/تعديل/حذف المشاريع
> - رفع/حذف/تعديل الملفات في storage

> **الأدمن (authenticated) فقط يستطيع:**
> - قراءة رسائل العملاء
> - إضافة/تعديل/حذف المشاريع
> - رفع/حذف/تعديل الملفات في storage

كل دا متطبق في `schema.sql` عن طريق **Row Level Security (RLS)** و policies خاصة بـ `anon` و `authenticated`.

## ⚠️ تحذير أمني مهم

- **ممنوع نهائيًا** وضع أي `service_role` أو **Secret Key** في:
  - `main.js` / `backend.js` / `supabase-config.js` / GitHub
- الـ `anon key` آمن للاستخدام العام (مصمم للواجهة الأمامية)، والأمان الحقيقي يعتمد على **سياسات RLS** — مش على إخفاء المفتاح.

## 🛡️ خطة حفظ البيانات (تم تنفيذها)

عند إرسال الفورم، الترتيب أصبح:
1. العميل يضغط **إرسال**
2. حفظ البيانات في Supabase (مع مهلة قصوى 2.5 ثانية)
3. فتح واتساب

**ولو Supabase فشل أو أبطأ، واتساب يفضل يشتغل دائمًا** — الفشل في الحفظ مش بيمنع واتساب إطلاقًا.

### 🆕 اللي أضافه التحديث ده

الموقع بيسجّل دلوقتي **كل** تواصل من العميل، سواء من **فورم** أو من **ضغطة واتساب مباشرة** على أي زر بالموقع (الفوتر، الزرار العائم، كروت التواصل، إلخ).

#### 1) حفظ بيانات الفورم
- البيانات نفسها (الاسم، التليفون، الخدمة، التفاصيل) بتتحفظ في `leads`.

#### 2) تتبع ضغطات واتساب المباشرة
- أي ضغطة على رابط `wa.me` في أي صفحة بتتسجل تلقائيًا (بدون ما تمنع فتح واتساب أبدًا).
- بتتسجل: **الصفحة اللي جاي منها** + **الرابط** + **الوقت**.

#### 3) أعمدة جديدة في جدول `leads`
| العمود | الوصف |
|--------|--------|
| `contact_type` | `form` (طلب فورم) أو `whatsapp` (ضغطة واتساب مباشرة) |
| `page_source` | الصفحة اللي حصل منها التواصل (`index.html`, `services.html`, ...) |
| `wa_link` | رابط واتساب المستخدم (إن توفر) |

> الاسم والتليفون بقوا **اختياريين** (nullable) لأن ضغطة واتساب المباشرة ممكن تتم من غير بيانات العميل.

### 🖥️ لوحة التحكم — تبويب "سجل تواصل العملاء"
- **فلترة** حسب النوع: الكل / طلبات الفورم / تواصل واتساب
- **ملخص سريع** بعداد لكل نوع
- **شارة نوع** لكل سجل (فورم 👈 أزرق / واتساب 👈 أخضر)
- عرض **المصدر** (الصفحة) و **الرابط** و **الرسالة**

### 🔒 الخصوصية
- لوحة التحكم بتعرض **الرابط** وبيانات المصدر فقط — مُش محتوى المحادثة داخل واتساب.
- بيانات العملاء لسه محمية بـ RLS (الأدمن فقط يقرأها).

## 💾 Backup

## ⚙️ ملاحظات مهمة

- **الموقع بيشتغل عادي حتى لو Supabase مش مربط** — بيستخدم المحتوى الثابت كاحتياط.
- بمجرد ربط Supabase وعمل جدول `projects`، الموقع هيقرأ المشاريع من قاعدة البيانات تلقائيًا (CMS).
- جدول `leads` بيخزن رسائل العملاء اللي بتتحفظ تلقائيًا عند إرسال الفورم.
- Data الرسائل والأدمن كلها محمية بـ Row Level Security (RLS).
